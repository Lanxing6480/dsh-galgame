# v1.2.1 — 多会话与安装兼容性补丁

## 修复

- GalGame 的默认输入区接管只匹配当前 `sessionId`。打开 GalGame 时，其他会话的输入区与提问/审批卡继续由原有界面处理。
- 每次视图挂载独立持有释放句柄；卸载一个视图不会提前释放另一个视图的接管。上游重新声明插槽后会重新注册，插件卸载时释放资源。
- Cordis、React 和 DSH 前端模块改为 optional peers，避免安装插件时自动下载另一套宿主依赖；运行时仍由 DSH 提供这些模块。前端 peer 范围显式包含 `^0.2.1-rc.3`。

## 验证与边界

- 95 项自动化测试通过：冒烟 13、DOM 26、表情/试演 51、共存 5。共存用例另在官方 DSH 0.2.1-rc.3 SlotCore 上通过，原版 1.2.0 的跨会话对照失败。
- 在独立配置和工作目录中，运行 DSH 0.2.1-rc.3、Node 24.21.0，以及反馈中列举的皮肤和其他插件，通过内置浏览器检查普通对话、流式转定稿和 GalGame 切换。详细版本与安装条件见 [隔离复测记录](../compatibility-2026-10-30.md)。
- **原反馈的「普通聊天正文消失」在原版与修复版中均未复现，因此本版本不宣称已解决该症状。** 已确认的接管缺陷位于输入区，尚不能据此推断正文消失的根因。
- 浏览器验证使用完整 DSH Web 链路和固定 SSE 响应，未覆盖 Electron 桌面壳、所有真实模型输出或反馈者未提供的精确插件版本。其他插件自身的预发布 peer 安装冲突不在本补丁修复范围内。

## 升级

在插件管理器中将 `@lanxing/dsh-galgame` 更新到 `1.2.1`，或执行：

```powershell
dsh plugin --profile web add @lanxing/dsh-galgame@1.2.1
```

使用 desktop 等其他 profile 时，替换 `--profile` 的值。保留原有 bundles 项，完成后重启对应 DSH 实例并刷新页面；无需改动聊天记录或其他插件配置。
